# Feature Specification: PageNotes - Web Page Note-Taking Extension

**Feature Branch**: `001-page-notes`  
**Created**: 2026-02-04  
**Status**: Draft  
**Input**: User description: "Google Chrome拡張機能でWebページにコメント/メモを残し、再訪問時に確認できる機能"

## Clarifications

### Session 2026-02-04

- Q: URLマッチングロジック - URLのどの部分までをメモの紐付けに使用しますか？ → A: パス完全一致（クエリパラメータとハッシュを無視）。例: `example.com/page?id=123#section` と `example.com/page` は同じメモを表示する
- Q: 1ページあたりのメモ数 - 1つのWebページに対して何個のメモを作成できるようにしますか？ → A: 1ページ1メモ（単一メモ方式）。シンプルで予測可能、管理UIが不要
- Q: メモUI初期表示位置 - ページを開いたときにメモがどこに表示されるべきですか？ → A: 画面右下隅（固定初期位置、ユーザーがドラッグで移動可能）
- Q: メモの最大文字数制限 - 1つのメモに入力できる文字数の上限は？ → A: 1,000文字（短〜中程度のメモに対応、ストレージ効率とUI表示の両立）
- Q: メモの自動表示動作 - ページを開いたときに、メモが存在する場合の表示動作は？ → A: 自動展開表示（すぐに内容が見える）。メモの価値を即座に提供

## User Scenarios & Testing *(mandatory)*

### User Story 1 - メモの作成と表示 (Priority: P1)

ユーザーがWebページを閲覧中に、特定の内容について記録を残したいと思ったとき、ページ上にメモを作成し、後で同じページを開いたときに自動的にそのメモを確認できる。

**Why this priority**: メモの作成と表示は本機能の核心的価値。これだけで基本的なユースケースが完結し、ユーザーに価値を提供できる。

**Independent Test**: 任意のWebページで拡張機能アイコンをクリックしてメモを作成し、ページをリロードまたは再訪問したときにメモが表示されることで完全にテスト可能。

**Acceptance Scenarios**:

1. **Given** ユーザーがWebページを閲覧している, **When** 拡張機能を起動してメモを入力し保存する, **Then** メモが画面右下隅に展開状態でオーバーレイ表示される
2. **Given** メモが保存されたページを閉じた, **When** 同じURLのページを再度開く, **Then** 以前に作成したメモが自動的に展開表示される
3. **Given** ユーザーがページを閲覧している, **When** メモが存在しないページを開く, **Then** メモ表示領域は空の状態で表示される

---

### User Story 2 - メモの編集 (Priority: P2)

ユーザーが既存のメモ内容を更新したいとき、メモを編集して変更を保存できる。

**Why this priority**: メモの内容は時間とともに変化する可能性があり、編集機能は実用性を大幅に向上させるが、新規作成ができれば最低限の価値は提供できる。

**Independent Test**: 既存のメモを持つページでメモを編集し、保存後にページをリロードして変更が反映されていることを確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** メモが表示されている, **When** ユーザーが編集ボタンをクリックする, **Then** メモが編集可能な状態になる
2. **Given** メモが編集モードである, **When** 内容を変更して保存する, **Then** 変更内容が即座に反映され表示される
3. **Given** メモを編集中である, **When** 変更を保存せずにキャンセルする, **Then** 元の内容が維持される

---

### User Story 3 - メモの削除 (Priority: P3)

ユーザーが不要になったメモを削除して、ページをクリーンな状態に戻せる。

**Why this priority**: メモの削除は整理整頓のために重要だが、メモの作成・編集機能があれば基本的な価値は提供できている。

**Independent Test**: メモを持つページで削除操作を実行し、ページリロード後にメモが表示されないことを確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** メモが表示されている, **When** ユーザーが削除ボタンをクリックする, **Then** 確認ダイアログが表示される
2. **Given** 削除確認ダイアログが表示されている, **When** ユーザーが削除を確定する, **Then** メモが即座に非表示になり保存データから削除される
3. **Given** 削除されたメモがあるページを開く, **When** ページを再訪問する, **Then** 削除されたメモは表示されない

---

### Edge Cases

- 同じドメインの異なるページ（例：`example.com/page1` と `example.com/page2`）では、それぞれ独立したメモが表示される
- URLにクエリパラメータやハッシュが含まれる場合（例：`example.com/page?id=123#section`）、これらは無視してパス部分のみでメモを紐付ける（つまり `example.com/page` として扱う）
- ページのコンテンツが動的に変化する（SPAなど）場合、メモの表示タイミングは適切か？
- 保存容量の上限に達した場合、ユーザーにどのように通知するか？
- 非常に長いメモテキストを入力した場合、UIが適切に対応できるか？（1,000文字制限に達したときの通知方法）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 拡張機能は、ユーザーが現在閲覧中のWebページに対してテキストメモを作成できる機能を提供しなければならない。メモの最大文字数は1,000文字とする
- **FR-002**: 拡張機能は、作成されたメモをページのパス部分（クエリパラメータとハッシュを除く）に紐付けて永続的に保存しなければならない。例: `example.com/page?id=123` と `example.com/page#section` は同じメモを共有する
- **FR-003**: 拡張機能は、保存されたメモが存在するページを開いたとき、自動的にメモを展開状態で表示しなければならない（内容がすぐに見える状態）
- **FR-004**: メモの表示は、オーバーレイ形式でページコンテンツの邪魔にならないように配置されなければならない。初期表示位置は画面右下隅とし、ユーザーがドラッグで自由に移動できること
- **FR-005**: ユーザーは既存のメモ内容を編集し、変更を保存できなければならない
- **FR-006**: ユーザーは不要なメモを削除できなければならない
- **FR-007**: 拡張機能は、メモの表示・非表示を切り替える機能を提供しなければならない
- **FR-008**: メモのデータは、ブラウザを閉じたり再起動したりしても失われてはならない
- **FR-009**: 拡張機能は、複数のページそれぞれに1つずつメモを保存し管理できなければならない（1ページあたり1メモ、異なるページには別のメモ）

### Key Entities

- **Note（メモ）**: Webページに対するユーザーのテキストコメント。1ページに対して1つのメモのみ存在する。主要属性は、メモ本文、作成日時、最終更新日時、関連付けられたページのURL（パス部分のみ）
- **Page Identifier（ページ識別子）**: メモを特定のWebページに紐付けるための識別情報。プロトコル+ドメイン+パス（クエリとハッシュを除く）を使用

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは30秒以内にメモの作成から保存まで完了できる
- **SC-002**: メモが保存されたページを再訪問したとき、1秒以内にメモが表示される
- **SC-003**: メモは画面右下隅に初期表示され、ユーザーが自由にドラッグ移動またはサイズ変更できる
- **SC-004**: 保存されたメモは、ブラウザ再起動後も100%保持される
- **SC-005**: 最大100個のメモを異なるページに保存しても、拡張機能のパフォーマンスが低下しない
