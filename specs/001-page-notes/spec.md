# Feature Specification: PageNotes - Web Page Note-Taking Extension

**Feature Branch**: `001-page-notes`  
**Created**: 2026-02-04  
**Status**: Draft  
**Input**: User description: "Google Chrome拡張機能でWebページにコメント/メモを残し、再訪問時に確認できる機能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - メモの作成と表示 (Priority: P1)

ユーザーがWebページを閲覧中に、特定の内容について記録を残したいと思ったとき、ページ上にメモを作成し、後で同じページを開いたときに自動的にそのメモを確認できる。

**Why this priority**: メモの作成と表示は本機能の核心的価値。これだけで基本的なユースケースが完結し、ユーザーに価値を提供できる。

**Independent Test**: 任意のWebページで拡張機能アイコンをクリックしてメモを作成し、ページをリロードまたは再訪問したときにメモが表示されることで完全にテスト可能。

**Acceptance Scenarios**:

1. **Given** ユーザーがWebページを閲覧している, **When** 拡張機能を起動してメモを入力し保存する, **Then** メモがページ上にオーバーレイ表示される
2. **Given** メモが保存されたページを閉じた, **When** 同じURLのページを再度開く, **Then** 以前に作成したメモが自動的に表示される
3. **Given** ユーザーがページを閲覧している, **When** メモが存在しないページを開く, **Then** メモ表示領域は空の状態で表示される

---

### User Story 2 - メモの編集 (Priority: P2)

ユーザーが既存のメモ内容を更新したいとき、メモを編集して変更を保存できる。

**Why this priority**: メモの内容は時間とともに変化する可能性があり、編集機能は実用性を大幅に向上させるが、新規作成ができれば最低限の価値は提供できる。

**Independent Test**: 既存のメモを持つページでメモを編集し、保存後にページをリロードして変更が反映されていることを確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** メモが表示されている, **When** ユーザーが編集ボタンをクリックする, **Then** メモが編集可能な状態になる
2. **Given** メモが編集モードである, **When** 内容を変更して保存する, **Then** 変更内容が即座に反映され表示される
3. **Given** メモを編集中である, **When** 変更を保存せずにキャンセルする, **Then** 元の内容が維持される

---

### User Story 3 - メモの削除 (Priority: P3)

ユーザーが不要になったメモを削除して、ページをクリーンな状態に戻せる。

**Why this priority**: メモの削除は整理整頓のために重要だが、メモの作成・編集機能があれば基本的な価値は提供できている。

**Independent Test**: メモを持つページで削除操作を実行し、ページリロード後にメモが表示されないことを確認することで独立してテスト可能。

**Acceptance Scenarios**:

1. **Given** メモが表示されている, **When** ユーザーが削除ボタンをクリックする, **Then** 確認ダイアログが表示される
2. **Given** 削除確認ダイアログが表示されている, **When** ユーザーが削除を確定する, **Then** メモが即座に非表示になり保存データから削除される
3. **Given** 削除されたメモがあるページを開く, **When** ページを再訪問する, **Then** 削除されたメモは表示されない

---

### Edge Cases

- 同じドメインの異なるページ（例：`example.com/page1` と `example.com/page2`）で、それぞれ独立したメモが表示されるか？
- URLにクエリパラメータやハッシュが含まれる場合（例：`example.com/page?id=123#section`）のメモの紐付け方法は？
- ページのコンテンツが動的に変化する（SPAなど）場合、メモの表示タイミングは適切か？
- 保存容量の上限に達した場合、ユーザーにどのように通知するか？
- 非常に長いメモテキストを入力した場合、UIが適切に対応できるか？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 拡張機能は、ユーザーが現在閲覧中のWebページに対してテキストメモを作成できる機能を提供しなければならない
- **FR-002**: 拡張機能は、作成されたメモをページのURL（またはURLパターン）に紐付けて永続的に保存しなければならない
- **FR-003**: 拡張機能は、保存されたメモが存在するページを開いたとき、自動的にメモを表示しなければならない
- **FR-004**: メモの表示は、オーバーレイ形式でページコンテンツの邪魔にならないように配置されなければならない
- **FR-005**: ユーザーは既存のメモ内容を編集し、変更を保存できなければならない
- **FR-006**: ユーザーは不要なメモを削除できなければならない
- **FR-007**: 拡張機能は、メモの表示・非表示を切り替える機能を提供しなければならない
- **FR-008**: メモのデータは、ブラウザを閉じたり再起動したりしても失われてはならない
- **FR-009**: 拡張機能は、複数のメモを同時に管理できなければならない（複数ページそれぞれにメモを持つ）

### Key Entities

- **Note（メモ）**: Webページに対するユーザーのテキストコメント。主要属性は、メモ本文、作成日時、最終更新日時、関連付けられたページのURL
- **Page Identifier（ページ識別子）**: メモを特定のWebページに紐付けるための識別情報。URLまたはURLパターンを使用

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは30秒以内にメモの作成から保存まで完了できる
- **SC-002**: メモが保存されたページを再訪問したとき、1秒以内にメモが表示される
- **SC-003**: ページのコンテンツと重ならない位置にメモが表示され、ユーザーが自由に移動またはサイズ変更できる
- **SC-004**: 保存されたメモは、ブラウザ再起動後も100%保持される
- **SC-005**: 最大100個のメモを異なるページに保存しても、拡張機能のパフォーマンスが低下しない
